Grinch

Choose where links open on your Mac. Grinch uses your JavaScript rules to send each link to a browser, profile, or app.

Download DMG View on GitHub

macOS 13+ · Universal binary

Release notes · Latest release only supported

What it is

  • Send links where you want them. Open work links in one browser, personal links in another, and meeting links in an app.
  • Use your browser profiles. Send links to a work profile, open a private window, or choose a new window in supported Chrome and Firefox browsers.
  • Clean up links. Remove tracking parameters or unwrap links before your rules choose where they open.
  • Menu-bar app. Reload config or open it in your editor without leaving the menu bar. Parse errors surface as ⚠️ with the failing line inline. With hideIcon: true, reopen Grinch from Spotlight or Finder to access config, log, and update actions in a window. The update button is disabled when the updater cannot check for updates.
  • Automatic updates. Grinch checks for updates automatically. You can check manually or turn automatic checks off from the menu bar.
  • Debuggable. Every resolve can be logged as JSON or text with the matched rule, opener, and modifier state. --list-rules prints the loaded rule table for cross-reference.
  • SSO / OAuth popups route through your rules. Sign-in requests from apps using ASWebAuthenticationSession use the same browser routing rules as other links.
  • Moving from Finicky? Most Finicky v4 configs work with Grinch. See the compatibility notes.

Install

Grab the DMG and drag Grinch.app to /Applications. Create a config as shown below, launch Grinch, then select it under System Settings → Desktop & Dock → Default web browser.

DMG=$(curl -fsSL https://api.github.com/repos/jamtur01/grinch/releases/latest \
  | grep -oE '"browser_download_url": "[^"]*\.dmg"' | cut -d'"' -f4)
curl -fsSL "$DMG" -o /tmp/grinch.dmg
hdiutil attach -nobrowse -quiet /tmp/grinch.dmg
ditto "/Volumes/Grinch "*/Grinch.app /Applications/Grinch.app
hdiutil detach "/Volumes/Grinch "* -quiet
open /Applications/Grinch.app

Always install to /Applications directly — running out of ~/Downloads triggers Gatekeeper translocation, which makes the same app appear multiple times in the default-browser picker.

Or install the community-maintained Homebrew cask: 

brew tap bric3/tap
brew install --cask grinch

The cask is maintained outside the Grinch project.

Or build from source:

git clone https://github.com/jamtur01/grinch
cd grinch
make run

Configure

Edit your existing Grinch config, or create ~/.config/grinch.js with the example below. Create ~/.config first if needed, and replace the browser targets if you use different apps. If your edits don't take effect, see which config Grinch uses.

module.exports = {
  default: "com.apple.Safari",
  rules: [
    { match: "github.com", open: "com.google.Chrome" },
  ],
};

Links to GitHub or its subdomains open in Chrome; other links open in Safari. A target can also be another app, such as Zoom. Choose Reload Config in the menu after editing.

Grinch applies matching URL rewrites in order, then checks rules from top to bottom. The first match chooses the app; default handles the rest. An open function returning null or undefined continues to the next rule. See the configuration guide for browser profiles, match types, rewrites, and options.

For the terminal commands below, use the installed binary or define this alias in your shell:

alias Grinch='/Applications/Grinch.app/Contents/MacOS/Grinch'
Grinch --test "https://github.com/"

The test prints the routing decision without opening a browser.

When a click goes the wrong way

A handful of CLI flags and a diagnostic log answer "why did that click go there?":

List the loaded rules

Grinch --list-rules prints every rule with its index, label, and target — pair with the diagnostic log to map a matchedRule.index back to the actual entry in your config.

0: github.com → com.google.Chrome

Open the diagnostic log

Grinch records config-load, runtime JavaScript, profile, and browser launch errors in a diagnostic file per app launch at ~/Library/Logs/Grinch/Grinch_<timestamp>.log. Set options: { logRequests: true } to add one resolve event per routed URL. Use Open Diagnostic Log in the menu bar to open the active file:

JSON is the default; set options: { logFormat: "text" } for readable text. Omitting the setting, or setting it to null or undefined, selects JSON. An invalid value keeps the current format, records a config error, and prints a warning without stopping routing. Grinch --validate shows the warning but still exits 0 if the config loads. Changing formats starts a new file, preserving the previous log; switched files use suffixes such as .1.log and .2.log.

Logging options take effect after the config's JavaScript is evaluated and its options are parsed, even if later engine construction fails. Errors before the first config's options are parsed use JSON. The menu opens the current file.

For example, a configuration error in JSON:

{"date":"2026-05-11T12:57:25-0400","event":"config_error","message":"SyntaxError (line 4)","path":"/Users/alex/.grinch.js","ts":1778518645.634}

The same event in text format:

2026-05-11T12:57:25-0400  config_error
  message: SyntaxError (line 4)
  path: /Users/alex/.grinch.js

For a different configuration, a resolve event might contain these routing details:

{
  "date": "2026-05-11T12:57:25-0400",
  "event": "resolve",
  "ts": 1778518645.634,
  "url": "https://github.com/foo",
  "final": "https://github.com/foo",
  "rewritten": false,
  "browser": "com.google.Chrome",
  "args": ["--profile-directory=Profile 1"],
  "strategy": "launch_new_instance",
  "opener": {
    "bundleId": "com.tinyspeck.slackmacgap",
    "name": "Slack",
    "pid": 731
  },
  "modifiers": {
    "shift": false,
    "option": false,
    "command": false,
    "control": false
  },
  "matchedRule": { "index": 2, "name": "github.com" }
}

launch_error records invalid URLs, missing browsers, and native launch failures even when request logging is disabled. It includes url, browser, strategy, and message; native errors also include errorDomain and errorCode. These events share the same log and rotation settings across config reloads. A resolve event records the routing decision; it does not confirm launch success.

Logs can contain complete URLs, including authentication tokens and personal data. Redact them before sharing. Report vulnerabilities privately using the security policy.

console.log/warn/error/info/debug remain on stderr and are not copied into the diagnostic log.

Profile failures produce profile_error events with the browser, file path, and message, even with request logging disabled. Unresolved Chromium display names suppress the launch; explicit Default and Profile N directory values need no file access. Firefox still receives -P <name> when validation fails. Reload Config refreshes both profile caches after file access or browser profiles change. Firefox warnings stay in the log without changing the status item. The first launch-suppressing Chromium error shows a warning icon and a Profile error: menu item, with the full message in its tooltip. This includes errors discovered on a click; a successful reload clears the warning unless the error recurs.

Grinch identifies the opener from the Apple Event's sender when available. Otherwise it falls back to the frontmost app, which may not be the original sender.

Headless checks

Grinch --validate loads the config and exits 0 (with the resolved path and rule count) or 1 (with the captured load error). Designed for editor save-hooks and CI:

$ Grinch --validate
grinch: config OK — /Users/james/.config/grinch.js
rules:  12

$ Grinch --validate
grinch: config invalid — SyntaxError: Unexpected identifier 'rules'. (line 4)
path:   /Users/james/.config/grinch.js
$ echo $?
1

Routing arbitrary URLs from scripts

Grinch registers a grinch: URL scheme so external tools (Shortcuts, AppleScript, shell scripts) can ask it to route a URL through the user's rules without setting it as the system default:

open grinch:https://example.com/path
open 'grinch:tel:+15551234567'        # tel: / webcal: / feed: are claimed too

A third shape, grinch://open/<base64-url>, accepts a btoa()-encoded inner URL. This is the envelope shape Finicky's published Chrome and Firefox addons emit, so pointing those addons at grinch://open/… instead of finicky://open/… makes "Open with Finicky" route through Grinch.

Sign-in links

Apps using ASWebAuthenticationSession send sign-in links through Grinch's normal routing rules.

Authentication requests received during startup wait for the initial configuration load attempt. Grinch returns an error if configuration is unavailable, routing suppresses the URL, or the browser cannot be opened. Requests canceled during startup do not launch a browser.

Authentication callbacks must return to Grinch to complete the pending session. Grinch forwards the initial URL as a normal browser tab and cannot observe later navigation. Apps that rely solely on the authentication-session callback can remain waiting after sign-in. Custom-scheme callbacks work on macOS 13 and later; HTTPS host/path callbacks require macOS 14.4 or later.

Grinch does not advertise ephemeral-session support. macOS may handle those requests in Safari instead, bypassing Grinch's routing rules.

Support and security

Only the latest published release is supported for issues and security fixes. Upgrade and reproduce the problem before filing a bug. Older releases do not receive backported fixes.

For bug reports and feature requests, follow the contributor guide. Report suspected vulnerabilities through private reporting, not a public issue. See the security policy for what to include and how to redact diagnostics.
